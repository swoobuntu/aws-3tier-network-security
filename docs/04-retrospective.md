# 04. 결과와 회고

[← README로](../README.md)

## 1. 구현 범위

**네트워크 · 보안 파트 (본인)**
- VPC 1개, 서브넷 16개(2 AZ), 커스텀 NACL 8개, 라우팅 테이블 2개, NAT Gateway 0개, VPC 엔드포인트 7종
- 보안그룹 참조 체인(경로 계층 아웃바운드 제한), Bastion 없는 SSM 접속
- AWS WAF(규칙 6개, CloudWatch Logs 기록), GuardDuty, CloudTrail(멀티리전 · 로그 무결성 검증), VPC Flow Logs

**팀 전체**
- CloudFront – Public ALB – WEB – 내부 ALB – WAS – RDS / Redis, 2 AZ 이중화
- CloudWatch 알람 → Slack 알림, Grafana 대시보드

## 2. 검증한 방법

| 방법 | 확인한 것 |
|---|---|
| AWS CLI 실조회 ↔ 설계 문서 대조 | 서브넷 · NACL · 라우팅 · 엔드포인트가 문서와 일치 |
| WAF 로그 분류 | 차단 사유 4종 구분, 업로드 오탐 원인(80KB vs 8KB) 특정 |
| AWS Cost Explorer | VPC 엔드포인트가 비용 1위(13일간 전체의 약 38%) — 설계 결정의 실제 비용 확인 |
| 시연 영상 (팀) | 장애조치(Failover)와 Auto Scaling 동작. 멘토 피드백에서 "구성 요소 전반을 시연 영상으로 검증한 팀"으로 언급 |

## 3. 정직하게 밝혀 두는 한계

- 교육용 계정에서 2주간 운영한 환경이고, 실제 사용자 트래픽은 없었습니다.
- AWS 콘솔에서 수작업으로 구축했습니다. 인프라 코드는 없습니다.
- CloudFront 우회 트래픽은 **탐지**만 하고 차단하지 않았습니다.
- AWS Config(구성 변경 추적)와 CloudFront 엣지 WAF는 구축하지 못했습니다.
- WAS 오토스케일링 그룹이 EC2 상태 기준 헬스체크를 써서, 애플리케이션 수준 장애 시 자동 교체가 되지 않는 공백을 사후 점검에서 발견했습니다.
- "Well-Architected 6 Pillars를 모두 충족했다"고 주장하지 않습니다. 각 결정이 어느 기둥에 해당하고 어떤 비용 · 운영 부담을 만드는지를 함께 기록했습니다.

## 4. 달라진 판단

**"켜져 있다"와 "동작한다"는 다르다**
Flow Logs는 활성 상태였지만 IAM 역할의 신뢰 대상이 잘못돼 실제로는 로그가 한 줄도 쌓이지 않았습니다.
이후로는 리소스를 만든 뒤 상태 표시가 아니라 실제 산출물(로그 · 지표)이 생기는지까지 확인합니다.

**보안 결정의 비용은 다른 곳에서 청구된다**
NAT 제거는 공격 표면을 줄였지만 비용이 가장 큰 항목이 됐고, 패키지 설치와 OS 패치 부담이 WEB/WAS 파트로 넘어갔습니다.
다음에는 결정 전에 비용과 운영 영향을 숫자로 비교해 팀과 먼저 공유하겠습니다.

## 5. 유지할 선택과 바꿀 선택

| 유지할 선택 | 바꾸고 싶은 선택 |
|---|---|
| 보안그룹 참조 체인 (인 · 아웃 양방향) | VPC 대역 — 확장 여유만이 아니라 필요한 IP 수를 산정한 근거를 함께 제시 |
| Bastion 없는 접속 | 단일 진입점 — 탐지에 그치지 않고 ALB 보안그룹을 CloudFront 대역으로 제한해 우회 차단 |
| 예약 대역 기반 NACL 관리 | 구축 방식 — 콘솔 수작업 대신 IaC로 관리해 변수 하나로 재구축 가능하게 |
| Count 선행 WAF 운영 | WAF 예외 — 경로 단위 예외 규칙을 실제로 적용하고 테스트 |
| 구축 후 실조회로 문서 검증 | ABAC — 다른 티어 접속이 실제로 거부되는지 테스트로 확인 |
